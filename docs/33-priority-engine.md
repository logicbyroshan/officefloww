# 33. Transparent Priority Engine

## 1. Design Invariant
Task priority is **never an unexplained black box**. Every priority score generated by the system includes an explicit, human-readable rationale detailing the operational context, deadline proximity, and downstream dependency blockers.

---

## 2. Priority Classification Matrix

| Level | Score | Condition | Example Rationale |
|:---|:---|:---|:---|
| **CRITICAL** | 10.0 | Due in < 6 hours OR order delivery SLA breached | `"CRITICAL: Due in 4.2 hours! Immediate action required to prevent order delay."` |
| **HIGH** | 5.0 | Due in < 24 hours OR directly blocks downstream printing/packing steps | `"HIGH: Due in 18 hours and directly blocks downstream printing and packing steps."` |
| **NORMAL** | 1.0 | Standard routine task within planned workflow buffer | `"Standard routine task in scheduled workflow."` |
| **LOW** | 0.5 | Background task, archiving, or buffer task | `"Non-critical cleanup task with flexible completion window."` |

---

## 3. Downstream Blockage Evaluation
In DAG workflows, if Task A (e.g. *Design Proofing*) is uncompleted, Task B (*Film Processing*) and Task C (*Press Setup*) are blocked. The priority engine detects dependency depth and elevates Task A's priority to `HIGH` or `CRITICAL` based on total queued downstream hours.
